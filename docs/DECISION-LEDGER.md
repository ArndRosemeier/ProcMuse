| 1 | **Build the full architecture from the start, as a library plus an app.** Owner, verbatim: *"i think thinking BIG is the correct approach here. Start building the full thing from the ground up, there is no need for a quick win. I would like this to be robust, without code multiplication ... this is no longer demo code, but a library + a to use it. That happens to be funky."* Rejected: the "live 4k" vertical slice first (Claude's proposal), because the owner judged it would be extended until it breaks. | all | scope | LANDED |
| 2 | **The owner merges nothing; Claude merges to `main`.** Owner, verbatim: *"You always merge to main yourself. Thats where i publish from."* So `main` only receives gate-green work. | process | publishing | LANDED |
| 3 | **Web Audio + AudioWorklet, pure-TypeScript DSP, synthesis first.** The engine renders sample by sample in TS (`EngineCore.process`), the same path live and offline. Rejected: native/WASM now (kept possible: the engine has no Web Audio dependency); samples first (synthesis is small, variable and fits the 4k spirit; a `sample` oscillator type can be added to `OscSpec`). Measured: ~11–20× realtime offline in Node at 44.1 kHz with all ten parts. Unproven: headroom on low-end phones. | `packages/engine` | performance and portability | LANDED |
| 4 | **One voice architecture; instruments and styles are data.** Drums included, every instrument is a `Patch` rendered by `Voice`; every genre is a `Style` over shared generators. Rejected: a class per instrument/genre (code multiplication). Pinned in `test/pins.test.ts`. | `instruments/`, `compose/` | no duplication | LANDED |
| 5 | **Every control is a declared `ParamSpec`; the UI is generated from specs.** Gives labels, descriptions (screen readers), presets and a host-app API from one declaration. Rejected: hand-built controls per panel. | `paramSpecs.ts`, `packages/ui` | accessibility and reuse | LANDED |
| 6 | **Changing style resets tempo, instruments and mix to the style's defaults.** Rejected: keeping user overrides across styles (instruments from one genre rarely fit another). Unproven: whether the owner wants a "keep my mix" option. | `engine/core.ts` | predictable styles | LANDED |
| 7 | **Flashes default OFF; reduced motion respected.** The 4k white-flash cuts would fail photosensitivity guidance, so the visuals carry a flash limiter and a `reduceMotion` switch. | `packages/visuals` | accessibility | LANDED |
| 11 | **A fifth scene, "Light cycles": a ride through a Tron-like city.** Owner, verbatim: *"Make another visualization that moves through a tron like world please."* One `SceneDef` (`scenes/tron.ts`) registered in `SCENES`: neon floor grid, neon-edged towers, five light cycles with walls of light (two oncoming), mirrored in the floor. Music: kick rolls a wave down the grid, bass lights tower edges, chords light windows, lead/arp drive the walls, hats the wall tops, snare the headlights. No white is added by the scene; flashes stay the composite's, behind the Flashes setting. | 12 | **Wow-factor instruments come from two voice features, not new synth classes.** Owner, verbatim: *"widen your instrument panel to include deep tribal horns and other instruments with a wow factor (tubular bells, organ sounds, things like that, maybe even something sounding like bagpipes)"*. Bells need partials that die at different rates and horns/pipes/voices need a fixed resonant body, so `Voice` gained `OscBase.fade` and `Patch.formant` (up to 6 oscillators); 16 patches were added as data and the tubular bell rebuilt on real tube partials. Organs also join the Pad part. A bagpipe is two patches (chanter on Lead, drones on Texture) because the Texture part holds the key note. Rejected: a drone oscillator pinned to a fixed note (it would ignore the key). Unproven: voicing by ear (measured to sit level with each category's neighbours). | `instruments/`, `compose/parts.ts` | variety without duplication | LANDED |
| 13 | **Phones get a sheet layout, not shrunken floating windows.** Owner, verbatim: *"Please make this phone compatible."* Below 640 px wide or 500 px tall (`SHEET_QUERY`) the workspace shows ONE panel at a time docked above a full-width dock (bottom sheet in portrait, right-hand side sheet in landscape); dock buttons switch it, ✕ closes it to show only the visuals. The floating layout and its positions are stored separately and untouched, so a rotated tablet keeps both. Touch: 44 px targets and 16 px inputs under `pointer: coarse`, hover styles behind `hover: hover`, no pull-to-refresh, safe-area insets. Audio: `WebEngine.create` resumes the context inside the tap (iOS ends the gesture at the first `await`), sets the Audio Session to `playback` so the iOS silent switch does not mute it, and resumes on the next tap after a call or lock. Rejected: dragging floating windows on a 390 px screen (they cover each other and the visuals, and a drag fights page scrolling). Visuals unchanged: the auto quality controller already drops render scale to 0.3 on a slow GPU. Unproven: real iOS/Android devices (headless Chromium phone emulation only); sound on a real iPhone. COPIES: 1 — checked, no duplication (grepped: `matchMedia`, `resume(`, `pointer: coarse`, `max-width: 600px` — the old one-off narrow-screen rule was removed in favour of the sheet). | `packages/ui`, `packages/web/src/webEngine.ts`, `apps/procmuse`, `scripts/e2e.mjs` | owner request | LANDED |
| 14 | **A sixth scene, "Dusk ride": a low, fast motorbike ride down a mirror road between wireframe mountains.** Owner, verbatim: *"I would like to have a visualization like this here. Does not need to be an exact match, but like that. Moving fast, like a race motorbike."* (with a reference image: blue wireframe mountains, wireframe palms, glossy road, glowing lane dashes, pink horizon glow). One `SceneDef` (`scenes/ride.ts`) registered in `SCENES`: a faceted triangle-mesh heightfield drawn as wireframe, palms as line drawings in planes across the road, a meandering road the camera leans into, and ONE mirror bounce inside the same march (the road reflects mountains, palms and glow). Fast: 24 units per travel unit (Light cycles: 8). Music: kick brightens the dashes and rolls a wave along the mountain wires, bass lights the wires, chords the palms, lead sways the fronds, hats the edge lines, pad/snare the horizon glow. Colours come from `palette()`, so the look follows the Colours setting (Ice or Synthwave come closest to the reference); no white is added beyond the steady dashes, so flashes stay the composite's. Narrow (portrait) screens get a wider view so both roadsides stay in frame. Unproven: frame rate on a real phone GPU (the auto quality controller lowers resolution and march steps). COPIES: 1 — checked, no duplication (grepped: GLSL function definitions across scene bodies via the `glsl.test` pin; noise/hash/rot/palette come from the prelude; the 2D segment distance `rideSeg` is the only one in any GLSL source). | `packages/visuals/src/scenes/` | owner request | LANDED |
| 15 | **Each fresh start of the app composes a new piece; the engine's default seed stays fixed.** Owner, verbatim: *"The music playing sounds similar or identical each time i start this. Is this a fixed seed?"* It was: the app started the engine without params, so every start used the Seed default 4096. Now `apps/procmuse` passes a seed from `crypto.getRandomValues` through `seedFrom` (the one seed-range seam, also used by New idea) to `WebEngine.create`. The `ParamSpec` default stays 4096 so the headless engine remains deterministic for host apps and tests, and presets/share links still restore their seed (a preset stores values that differ from the default, and applying one resets the rest to defaults). Deliberate reuse: set the Seed control, or open a share link. Rejected: a random spec default (would make the engine non-deterministic and break presets that omit the seed). e2e proves two starts differ and a share link pins its seed. COPIES: 2→1 — `seedFrom`/`SEED_LIMIT` in `engine/paramSpecs.ts` (the spec `max: 999999` and New idea's `% 1000000` were two spellings of the range; pinned). | `packages/engine/src/engine/`, `apps/procmuse/src/main.ts`, `scripts/e2e.mjs` | owner report | LANDED |
