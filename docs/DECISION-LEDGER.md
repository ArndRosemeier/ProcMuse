| 15 | **Each fresh start of the app composes a new piece; the engine's default seed stays fixed.** Owner, verbatim: *"The music playing sounds similar or identical each time i start this. Is this a fixed seed?"* It was: the app started the engine without params, so every start used the Seed default 4096. Now `apps/procmuse` passes a seed from `crypto.getRandomValues` through `seedFrom` (the one seed-range seam, also used by New idea) to `WebEngine.create`. The `ParamSpec` default stays 4096 so the headless engine remains deterministic for host apps and tests, and presets/share links still restore their seed (a preset stores values that differ from the default, and applying one resets the rest to defaults). Deliberate reuse: set the Seed control, or open a share link. Rejected: a random spec default (would make the engine non-deterministic and break presets that omit the seed). e2e proves two starts differ and a share link pins its seed. COPIES: 2→1 — `seedFrom`/`SEED_LIMIT` in `engine/paramSpecs.ts` (the spec `max: 999999` and New idea's `% 1000000` were two spellings of the range; pinned). | `packages/engine/src/engine/`, `apps/procmuse/src/main.ts`, `scripts/e2e.mjs` | owner report | LANDED |
| 16 | **Many more styles, and the music moves between them by itself.** Owner, verbatim: *"Right now i can identify basically 2 music styles here, some serene no percussion sounds and then the synth pop loop. Possible to have a lot more styles here?"* Cause: seven styles existed, but nothing ever left the opening one (Demoscene), so what was heard was one style's quiet sections (intro/break, below the drums' `minEnergy`) and its drops. Two changes, both on existing seams: (1) twelve new styles as data — Drum & Bass, Trap, Disco Funk, Chiptune, Dub, Jazz Lounge, Bossa Nova, Epic Cinematic, Tribal Ritual, Highland, Cathedral, Tropical — giving 19, with four new generator pattern families (bass `octave`, `riddim`; chords `skank`, `comp`) where a genre needed a rhythm the generators could not play; (2) the journey: `music.journey` (Style changes: Never/Rarely/Sometimes/Often = off/128/64/32 bars, default Sometimes). The composer plays an outro when a piece has run its course and starts the next piece in a style it has not just played, with fresh themes and a new auto key; the engine adopts it at the bar line and announces it. Old instruments now ring out on any swap (`Mixer` `retiring`) so a style change never cuts a tail. Every patch is now some style's default (pinned), so automatic variety reaches the whole instrument panel. Shortcuts: digits 1–7 (one per style) became `[` / `]` previous/next style, since 19 styles do not fit digit keys. Rejected: presets as "styles" (a preset only changes mix and instruments, not rhythm, harmony or form); picking a random opening style (startup is ledger 15's fresh seed; the journey brings a new style within minutes either way). Unproven: voicing and mix of the new styles by ear (audition: `procmuse/auditions/new-styles.wav`). COPIES: 2→1 — lo-fi's and ambient's inline forms became `GROOVE_FORM` / `DRIFT_FORM` in `styles/base.ts`, shared by the new styles; the hand-listed style ids in the styles pin now come from `BUILTIN_STYLES` (grepped: `form: {`, style id literals, `hit(s,` template loops in `harmony.ts`, folded into `hitAll`). | `packages/engine/src/compose/`, `engine/core.ts`, `engine/paramSpecs.ts`, `mix/mixer.ts`, `apps/procmuse/src/shortcuts.ts` | owner request | LANDED |
| 17 | **The start screen's title sizes to its card, so nothing overflows it.** Owner, verbatim: *"Small issue, the title screen has an unneccessary horizontal scroll bar"*. Cause: the letter-spaced "ProcMuse" is about 8.2em wide, 653 px at its 5rem size, inside a card whose content box was 496 px; the card has `overflow-y: auto` (short landscape phones), which makes its `overflow-x` `auto` too, so the overflow showed as a scroll bar on every desktop size (measured 1024–1920 px wide, and 844×390 and 360×640 phones). Fix at the cause: the card has a definite border-box width `min(40rem, 100vw - 32px)` and is an inline-size container, and the title is `min(5rem, 11.5cqi)`, so it always fits; 40rem keeps the desktop title near its old size. Rejected: `overflow-x: hidden` (would clip the title instead of fitting it). The e2e now checks the card itself (not only the page) on desktop and phone; it failed on the old CSS. COPIES: 1 — checked, no duplication (grepped: `pm-start`, `overflow`, `vw` in `apps/procmuse` and `packages/ui`; the desktop and phone start checks share one `startFits` helper in `scripts/e2e.mjs`). | `apps/procmuse/src/app.css`, `scripts/e2e.mjs` | owner report | LANDED |
